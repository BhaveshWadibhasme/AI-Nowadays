Interview · 20VC

Agent = model + context + harness: eight takeaways from Harrison Chase on 20VC

LangChain reshared Sydney Runkle's (Product @ LangChain) takeaways from Harrison Chase's conversation with Harry Stebbings on 20VC: “It's underrated how hard it is to build agents!” An agent is model plus context plus harness, and you can improve it by tweaking any of the three. The highest-ROI move is to optimize context first (where domain knowledge lives), then the harness, then the weights.

Continual learning is a loop: run an agent, collect traces, aggregate learnings, fix something, measure the fix, repeat, with the fix landing in any of the three layers. Memory is still massively unsolved but massively important, and the hardest part is distilling learnings from traces, which is very domain specific. Builders worry about accuracy, cost, latency and security, and cutting cost starts with visibility into spend, then controls, then agent optimizations, which is how LangChain reduced its own coding agent spend.

Model routing is most effective in the harness, where the context for the routing decision lives. Open models handle narrower tasks today (small parts of the loop, or specific post-trained domains) but will power more core loops as they improve, and the future holds both horizontal agents that use vertical agents, with infrastructure needing to change for agents doing background work at a rate humans cannot. The full episode is on YouTube; yesterday's page covered Harry Stebbings' notes from the same conversation.

Why it matters

Context first, then harness, then weights is a practical order of operations for improving an internal agent before anyone talks about fine-tuning, and the cost pipeline (visibility, controls, then optimization) is easy to adopt in a department.

Research · Google Research

Harness² through LangChain’s lens: traces and evals

Another Sydney Runkle repost: Harness² from Google Research offers techniques for recursive self-improvement (RSI) on the agent harness with a fixed model. They call it “harnessing,” but you may know it as hill climbing or continual learning. It works at two levels: at the task level it analyzes a trajectory, proposes a change, validates it and commits it if validated; at the harness level it learns which changes are effective so task-level optimizations get better over time.

Sydney notes the pattern is very familiar at LangChain and comes down to two units: the trace (the trajectory of each run, since Harness² requires each edit to be justified by evidence in a trace) and the eval (whether a change actually made the run better).

Why it matters

If you are evaluating self-improving agents, the precondition is the same either way: good traces and trustworthy evals. Our Harness² use-case guide on this site goes deeper on piloting it safely.
