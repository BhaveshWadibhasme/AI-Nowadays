Weekly Deep-Dive: Agents that run operations — Skills, MCP, specs and tracing

Agentic Ops MCP Skills Refinery Knowledge-Graph RAG Observability Governance
Thin week

This was a thin week for new energy case studies. bp Genie, PETRONAS PetroVisor, TGS Scout and UptimeAI were already covered in the 13 Nov and 20 Nov issues. So this issue covers the strongest new production agent stories (13 Nov to 26 Nov) plus one refinery story from June 2026 that maps directly onto delayed-coker work.

This week

The production agents this week had a few things in common. Expert knowledge was written down as Skills or specs, systems were wired in through MCP, a person approved anything high-impact, and every step was traced. The big refinery result also came from operators trusting the tool, not from a bigger model.

Five pieces: Banco BMG’s always-on DevOps agent resolves 62% of incidents with no human; U Mobile AiDaH, an agentic helpdesk on Bedrock AgentCore, cuts tickets by up to 84.5%; TotalEnergies Port Arthur’s AI operations assistant on a delayed coker; Mitsubishi Heavy Industries’ hybrid knowledge-graph RAG for industrial documents; and an analyst view that architecture is the bottleneck, and agents are software to engineer.

Problem

The bank runs a hybrid, multicloud platform with 1,150+ services, 9.1M+ customers and 2B+ requests a month. A symptom would show up in one service while the root cause sat several hops away, so threshold alerts fired only after customers were already hit. The worst case was the payroll-loan product, which brings in the most revenue.

Approach

AWS DevOps Agent was connected to the existing observability stack (Dynatrace, Elasticsearch, Freshservice, Kubernetes audit logs). Engineers’ tribal knowledge (architecture, dependencies, change-impact patterns) was written into custom Skills, starting with the product that had the scarcest knowledge. Custom MCP servers reached systems with no ready-made integration. It was rolled out in phases.

Results

It has run in production for months. It investigates 350+ events a day and analyses more than 1 TB of logs a day. MTTR fell 85%, from about 2 h to 18 min. In a sample of 300+ investigations it resolved 62% with no human. It detects issues up to 6 h earlier.

Lessons

(1) Encode the scarcest, highest-impact knowledge first. (2) The agent is only as good as the signals it can see, so treat custom MCP servers as first-class. (3) Autonomy changes the operating model: engineers move to building Skills and resilience. If you plan for it as a drop-in runbook replacement, you lose the value. Automatic fixing comes next, with a person kept in charge.

Pitch

Propose a “Root-Cause Skill” pilot for one critical unit’s alarms or maintenance work orders. Encode the senior engineer’s diagnostic playbook as a Skill, connect PI, SAP PM/Maximo and SharePoint through MCP, and measure time-to-diagnosis and the share of cases resolved without escalation.

U Mobile AiDaH: an agentic helpdesk on Bedrock AgentCore cuts tickets by up to 84.5%

Problem

Every routine diagnosis needed someone to pull interface logs, query billing-system eligibility APIs and check policy knowledge bases across separate portals. Tickets then escalated to back-end IT.

Approach

A six-layer architecture on Amazon Bedrock AgentCore, with a managed agent runtime, built-in memory, gateways that expose MCP tool definitions per domain, and role-based access control. It was built spec-first with Kiro: requirements, design and tasks were written and reviewed before any code was generated. That made each new domain a repeatable unit of work (new gateway, MCP tools, RBAC entries). The team shipped on 12-week sprints.

Results

It grew from a 2-use-case PoC to 150+ documented scenarios across six divisions within a year. From January to September 2026, provisioning and network tickets fell 84.5%, general inquiries 81.6% and billing tickets 48.7% (internal measurement).

Lessons

The agent-to-tool boundary is where designs fail. Write that contract and its permissions down before generating code. A managed runtime and memory remove infrastructure you would otherwise have to run.

Pitch

Present “one domain = gateway + MCP tools + RBAC + spec” as the repeatable template for scaling from one maintenance assistant to many (reliability, turnaround planning, HSE lookups) without redesigning each time.

Related: NTT DATA used Datadog Agent Observability on AgentCore to trace prompts, reasoning, tool calls and agent handoffs. It cut inference cost by 50% through evaluation-driven model choice and MTTR by 70%, and stood up its evaluation framework in under a week.

TotalEnergies Port Arthur: AI operations assistant on a delayed coker unit

Problem

On the DCU console at a 238k bpd refinery, steam disturbances cause pressure dips, compressor trips and flaring. Operators had little time to decide which non-critical equipment to shed steam from. High alarm volumes overwhelmed less experienced operators.

Approach

Honeywell Experion Operations Assistant, using its Experion Python Module, integrated with the HALO Lookahead Runway. The four use cases were steam-disturbance prediction, drum-cycling prediction, heater-spalling prediction and Enhanced Alarm Decision Support (EADS). EADS uses historical alarms, past responses and P&IDs, and SMEs validated its guidance. The pilot started in October 2024.

Results

Steam pressure dips are now predicted 10 to 18 minutes earlier, about 18 minutes on average, after feature engineering on volatility, rate, threshold distance and acceleration. TotalEnergies reports that accuracy rose by 85%. Operators have acted on at least two AI alerts. Heater spalling prediction reached about 75% accuracy, updated every 2 h over a 28 to 30 day cycle. Drum-cycle prediction reached 75%, but it was dropped because drum switching depends on factors outside the model. EADS covers 300+ coker tags and is in extended evaluation.

Lessons

Feature engineering, not model choice, moved lead time. Drop a use case when it can’t drive the decision, even if its accuracy is good. “Not plug-and-play, needs support.” Involve operators from day one.

Pitch

This is a public benchmark for coke-prediction work. Position your coke model as one predictive use case inside a console “operations assistant” with alarm decision support grounded in P&IDs and past events. Borrow the go/no-go discipline: keep a use case only if operators act on it.

Case study 04 · MHI Technical Review Vol. 63 No. 3, 2026

AI Engineering · Context

Mitsubishi Heavy Industries: hybrid knowledge-graph RAG for industrial documents

Knowledge-Graph RAG Industrial documents Retrieval
~59% → 89%retrieval, high-pressure-gas rules
~28% → 69%retrieval, export-control rules

Problem

Regulations, standards, design specs and manufacturing instructions cross-reference each other through hierarchy, citations and defined terms. Plain chunk-based RAG misses the supporting evidence.

Approach

Start with hybrid retrieval (multilingual vector search plus BM25, fused with RRF, then reranked). Then expand the candidates through a knowledge graph with structural links (hierarchy, citations, references) and conceptual links (terms, synonyms, related concepts). LLMs propose node and relationship types, and people review the ontology.

Results

Retrieval of relevant documents and answer accuracy both improved on internal test sets: high-pressure-gas laws, foreign-exchange and foreign-trade (export-control) laws, and the EU AI Act. The report’s PDF lists retrieval rising from about 59% to 89% on the high-pressure-gas rules and from about 28% to 69% on the export-control rules.

Lessons

Many failures in industrial RAG are really about following references, not about embeddings. Use the LLM to bootstrap the ontology, then keep a person reviewing it.

Pitch

Use it for engineering standards, Management of Change (MOC) and HSE procedure lookups that cite other documents. Run a small A/B test of a graph-expansion layer on top of your existing retrieval, on a gold set of 50 to 100 real engineer questions.

Case study 05 · Gartner, 20 Nov 2026 · arXiv 2611.23260

AI Engineering · Tools + agents

Analyst and research view: architecture is the bottleneck, and agents are software to engineer

Governance Architecture Software engineering
4steps in the Gartner abstract
355papers in the lifecycle survey

Problem

Gartner’s public abstract of “Scale Agentic AI With Agent-Native Architecture” (20 Nov 2026) says enterprise agentic AI is held back by architecture, not agent intelligence. The lifecycle survey’s point is that prompt, model or interface changes can break behaviour that was already accepted.

Approach

Gartner recommends four steps: assess the readiness of the application portfolio, put dynamic domains first, deploy a reference architecture, and engineer agent operability with human oversight. arXiv 2611.23260, “Software Engineering for LLM-Based Agents: A Lifecycle-Oriented Survey” (Nanjing University, NTU, Tsinghua, PKU), reviews 355 papers across requirements, architecture and design, implementation and integration, testing and assurance, and maintenance and evolution.

Results

The survey’s finding is that agents need regression testing like any other software, because prompt, model or interface changes can break behaviour that was already accepted.

Lessons

Architecture is the bottleneck. Treat agents as software to engineer, and retest when the prompt, the model or the interface changes.

Pitch

Use these two to frame a department “agent readiness” review. Score target systems on API/MCP exposure, data semantics and permission models before choosing use cases. Then set up regression evaluations for every prompt or model change.

For the week

Consulting playbook

  1. Encode first, automate second: turn your scarcest expert’s diagnostic playbook into a Skill or spec before you build an agent (BMG, U Mobile).
  2. Make “one domain = tools + permissions + spec” the unit you scale.
  3. Gate high-impact actions behind a person, and trace everything (prompt, tool call, cost) from day one (NTT DATA).
  4. Keep a use case only if operators act on it. Accuracy alone is not the bar (TotalEnergies’ drum-cycle model was dropped at 75%).
  5. Fix retrieval structure before swapping models (MHI’s graph expansion).

Hands-on

Framework trend

Agent Skills plus MCP servers. Banco BMG and U Mobile both scaled by packaging know-how as Skills and connecting systems through custom MCP servers. Hands-on: build a small MCP server over a CSV or SQLite of historian-style tags and work orders, write a “root-cause” Skill (SKILL.md plus scripts) that uses it, and add OpenTelemetry tracing (for example LangSmith or Langfuse) so every tool call and its cost is visible.
