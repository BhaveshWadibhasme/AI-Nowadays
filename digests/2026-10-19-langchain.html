LangSmith · Post-training

Your agent traces can become training data

Ankush Gola (Co-Founder, LangChain) argues that agent traces are larger and far more information-dense than traditional traces, and serve a different purpose: continually improving the agent, not just finding where a system is slow or broken. He names two ways to do that: harness engineering (Engine) and post-training.

For post-training, traces become fuel for SFT examples (successful production trajectories teaching a base model), tasks (real production inputs becoming eval and RL tasks), verifiers (feedback from users and other sources defining success criteria), and tool snapshotting (traces plus source code reconstructing tools and state to build agent environments).

Why it matters

Production traces you already collect can feed evals, RL tasks and fine-tuning data, which makes observability a path to better agents rather than just a debugging tool.

LangSmith · Public beta

Four ways to use AI search in LangSmith

LangSmith's AI search lets you search traces by behavior in plain language. LangChain lists four uses: debug failures that don't throw errors (search "the agent gave an incomplete answer" and check whether the problem is in the prompt, tools, retrieval or routing); turn real usage into eval datasets by searching for a behavior and adding the relevant traces; send traces to human review by sending matches such as "the user disputed the agent's answer" to an annotation queue; and find product gaps with searches like "requests for integrations we don't support".

AI search is available in public beta on LangSmith cloud at no additional cost. The blog post explains how it works, how it stays fast across large volumes of production traces, and what's next.

Why it matters

Searching traces by behavior instead of by error codes surfaces the silent failures and unlabeled edge cases that matter most when you build eval sets for internal agents.

Managed Deep Agents · Security

Sandbox proxies keep your credentials out of the agent's reach

Caspar Broekhuizen (Agents at LangChain) explained how Managed Deep Agents defends against malicious packages that try to send your credentials to an unknown server. The agent's code runs in a sandbox, an isolated machine for each conversation, and every request leaving the sandbox goes through a proxy that runs outside of it.

The proxy only lets through the services you allow and blocks everything else. When the agent calls a service you've configured, the proxy adds your token on the way out, so the token never lands in the sandbox and the agent never has direct access to it. The post includes a step-by-step video.

Why it matters

Keeping secrets outside the sandbox and allow-listing egress is the pattern security teams will ask about before approving agents that run code.

Scaling Agents in Healthcare & Life Sciences

LangChain's latest guide brings together lessons from Madrigal Pharmaceuticals, Abridge and Vizient on moving healthcare and life sciences agents from experimentation into trusted production systems.

Interview · 20VC

Harrison Chase on coding-tool spend, neutral harnesses and memory

LangChain reshared Harry Stebbings' (Founder @ 20VC) notes from a conversation with Harrison Chase. The post says LangChain is now worth $1.2BN and serves 35% of the Fortune 500, and that it spends 30% of its engineering salary on coding tools, a share that has fallen over the last two months even as token usage went up. The team tracks coding agent usage in LangSmith, sets budgets, and its in-house cloud coding agent uses prompt caching and routing to cut costs.

Harrison argues harnesses need to be neutral: if memory is tied to the harness and the harness is tied to the model, a company ends up stuck. He expects memory, rare in agents today, to become incredibly common, and sees consumers using both horizontal and vertical agents. For large enterprises, cost has risen as a concern but still ranks below accuracy and above latency.

Why it matters

The neutral-harness and memory points are a practical checklist for avoiding model lock-in when choosing an agent stack for your department.
