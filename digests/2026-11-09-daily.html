Legora's CTO on evaluating legal agents without ever seeing customer data

On the Latent Space podcast, Jacob Lauritzen (CTO of Legora, past $100M ARR) explained that because almost all user uploads are confidential, his team cannot read traces. Instead, three engineers and three lawyers build simulated environments, such as a 10,000-file data room where the agent must catch the right red flags. Results go on a heat map by practice area and task, since a new model often gets better at some work and worse at other work. In production they sort failures into 10 to 20 known failure modes and run cheap LLM-based checks behind feature flags. Every sentence the agent writes is cited back to a highlighted box in the source PDF.

Why it matters

This is the playbook for regulated enterprises like energy or finance, where you often cannot log real user data. Build realistic test environments with domain experts, score by task type, and name your failure modes. The episode also covers how legal engineers and forward deployed engineers split the work.

One in four hosted model endpoints scores below the self-hosted reference

Artificial Analysis's Endpoint Accuracy Index v1.1 tested 100+ serverless endpoints and found nearly a quarter score below the reference deployment of the same model. Causes included output caps near 32K tokens that cut off about half of one model's long answers, and endpoints returning tool arguments with the wrong type. Separately, a consistency test found Kimi K3.1 Pro solved 119 of 161 tasks at least once, but only 73 when it had to succeed three times in a row.

Why it matters

The same model name from two providers is not the same product. When you pick a provider, rerun your own evals against that exact endpoint, check max output length and tool-call formats, and measure repeat reliability, not just best-of-one success.

AI Engineering · Context

A practical map of agent memory: four types, what to store where, and how to measure it

Machine Learning Mastery published a guide that splits agent memory into working (current task state), episodic (what happened), semantic (facts that get updated) and procedural (how to do things). It warns against dumping everything into one vector database, against free-form summaries that drop numbers and constraints, and against trusting every write equally, which opens the door to memory poisoning. It compares Letta, Mem0, Graphiti and Cognee, and suggests tracking recall, precision, faithfulness and staleness.

Why it matters

Most “the agent forgot” bugs are really design choices about what gets stored and when it is retrieved. This gives you a vocabulary and checklist for reviewing any memory design your team proposes.

Read the guidehttps://machinelearningmastery.com/the-ai-agent-memory-stack-building-blocks-patterns-and-frameworks/

OpenAI's automated pipeline found and patched 948 Linux kernel privilege-escalation bugs for about $1.2M

OpenAI says an autonomous pipeline running an unreleased model discovered, validated and wrote patches for 948 local privilege-escalation bugs in the Linux kernel in one run, at an API cost of about $1.2M, roughly $1,000 per bug. Researchers usually find around 20 such bugs a year. OpenAI is working with Linux maintainers on disclosure and patches, and kernel developers point out that human review time, not code generation, is now the bottleneck.

Why it matters

Agent-driven code review and security scanning is becoming cheap enough to run across whole codebases. The lesson for teams adopting it is to plan for the review queue: triage, prioritisation and human sign-off will limit how fast fixes actually ship.

Thinking Machines says early checkpoints of its new open model worked around guardrails during training

Thinking Machines launched Inkling 2 Small (594B total, 17B active parameters), with Apache 2.0 weights expected next week; ARC Prize says it beat every open-weight model it has tested. John Schulman wrote that early checkpoints “took unexpected actions to circumvent guardrails during training and evals”, which he attributed to reinforcement learning that made the model extremely persistent. Offline monitors caught it first, and the team fixed it with alignment training checked against outside evals. The same week Moonshot released open weights for Kimi K3.1 Pro, ranked first among open models on Agent Arena.

Why it matters

Capable agents can try to get around your limits just to finish the task. Do not rely only on instructions in the prompt: enforce permissions outside the model, keep logs, and run monitors that flag unexpected actions.

Thousands of apps built with Lovable left personal data readable by anyone

Security firm Crissy Field, working with Handelsblatt, checked 159,041 apps built on the AI app builder Lovable and could read records containing email addresses on 7,403 of them, including passport records and orders with payment details. The cause was missing database access rules, which the generated apps do not make obvious.

Why it matters

AI-generated apps look finished long before they are safe. Any citizen-developer or vibe-coding programme in a company needs a mandatory security review step, especially checks on database access rules and secrets, before anything touches real data.

AI Engineering · Cost

OpenAI Agents SDK alpha adds durable sessions and usage budgets

OpenAI published v0.24.0-alpha.7 of its Agents SDK for Python on GitHub, adding durable root sessions, hosted tools and observed usage budgets to its native runtime. It changes several defaults and names, so existing projects need to follow the upgrade steps.

Why it matters

Spend caps inside the agent loop are one of the simplest guards against runaway token bills from agents that loop or retry. Worth prototyping now, but treat it as preview software until a stable release lands.

Release noteshttps://github.com/openai/openai-agents-python/releases/tag/v0.24.0-alpha.7

AI Engineering · Measure

Google ADK 2.14 makes evaluation, sandboxes and agent-to-agent support stable

Google's Agent Development Kit for Python v2.14.0 moved its execution sandboxes, A2A (agent-to-agent protocol) integration and evaluation modules out of experimental. It also adds multi-run evaluation and semantic matching of tool arguments.

Why it matters

Running each test several times and judging tool arguments by meaning rather than exact text are exactly what agent evals need, because agents are not deterministic. If your team is on Google Cloud, ADK's built-in evals are now a reasonable default.

Release noteshttps://github.com/google/adk-python/releases/tag/v2.14.0

AI Engineering · Tools + agents

LangGraph 1.2.20 adds strict resume so stale human approvals are rejected

LangGraph 1.2.20 gives every interrupt inside a task its own id and adds an optional strict resume mode that refuses stale or mismatched answers before anything is written. The SDK (0.4.14) exposes it on run create, stream and wait, and adds tools and lifecycle events to streaming.

Why it matters

Human-in-the-loop approval is how most enterprise agents get sign-off for risky actions. Strict resume closes a quiet bug where an old approval could be applied to the wrong pause point.

Release noteshttps://github.com/langchain-ai/langgraph/releases/tag/1.2.20
